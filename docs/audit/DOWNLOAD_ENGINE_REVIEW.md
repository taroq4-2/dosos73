# Download engine and storage integrity review

Source baseline: `1e46c56ce6028bdbae51ae1f80091115cd614e0b`. This workstream inspected the direct download, HTTP representation, queue, network recovery, publication and native integration interfaces. Results reported by earlier releases and CI are historical evidence; current execution is recorded in [TEST_EVIDENCE.md](TEST_EVIDENCE.md).

## Lifecycle evidence from source

| Step | Observed implementation and limits |
|---|---|
| Probe and selection | `DirectDownloader.analyze` uses HEAD; 403/405/501 can fall back to a bounded byte probe, and 416 to one plain GET closed without consuming the full file. The native route maps a bounded metadata document into supported formats; no playlist, remote EJS fetch or inherited configuration is enabled. HEAD establishes proposed format, not payload identity. |
| Scheduling | `DownloadQueue` serializes journal changes under its mutex and keeps a leased task separate from waiting jobs. Batch handoff records durable delivery identities before acknowledgement, so an unrelated failure must not lose queued jobs. Transfers remain single-job; opt-in parallel ranges run two workers for one file. |
| Network interruption | `NetworkSettings` binds DNS/sockets to a permitted Android network. `NetworkRecovery` registers observers before starting; acquisition/loss retries are bounded, and ordinary user cancellation is not retried. Background timing and OEM scheduler behavior are not inferred from JVM tests. |
| Direct resume | `ResumeJournal` synchronizes durable data before atomically recording the offset. Its hashes bind the initial and final redirect URL, and `DirectDownloader` requires a strong ETag, matching exact range and total, identity encoding and consistent lengths. HTTP 200 replaces rather than appends; HTTP 416 allows one new full request. No guaranteed resume for origins without reliable validators/ranges. |
| Parallel transfer | `ParallelDownloader` admits two isolated ranges only after an exact one-byte probe and strong ETag. Both segments validate origin/representation and length, synchronize and are merged into a temporary file before an atomic replace. Incompatible ranges fall back once to serial; partial segments are not used as a resumed checkpoint. Additional temporary storage may be required. |
| Media/local conversion | `MediaEngine` uses pinned yt-dlp, the proxy and constrained format IDs. Native media downloads restart rather than append across interrupted invocations. Local conversion is separate, bounded to local protocols, and the retained source is read-only. Genuine provider changes and format/region/authentication limitations remain external. |
| Verify and publish | `TransferProcessor` validates output type/duration as applicable, and `OutputStore` requires exact destination size and SHA-256 before commit. Pending MediaStore publication and SAF rename are recorded with task-specific receipts. `PublicationReceipt.recover` uses names, recorded membership and hashes rather than trusting a partial name or the provider alone. Failed acknowledgement retains durable state. |

## Remediation records

| ID / severity | Reproduction, impact and root cause | Implemented change and regression |
|---|---|---|
| **DL-01 / medium** | A known PDF/media/archive probe succeeds; GET 200 or a matching 206 responds with an explicit JSON/XML/plain-text provider error. Baseline `HttpRepresentation.requireIdentity` rejects HTML and multipart but would admit these bodies; a nonempty generic file can be verified and published as the wrong payload. | `DirectFileName` classifies only known binary choices, `DownloadService` passes this to `DirectDownloader` and `ParallelDownloader`, and successful response validation rejects typed error bodies before staging changes. `binaryHeadFollowedBySuccessfulErrorBodyCannotReplaceStaging`, `structuredErrorInMatchingRangeLeavesDurableCheckpointUntouched`, and `explicitGenericFilesAndOpaqueBinaryResponsesRemainSupported` cover the defect and compatibility. |
| **DL-02 / low** | A direct origin returns 403/404/429/503 and its body declares HTML or compressed encoding. Before the change, representation validation threw a generic payload error before HTTP classification, hiding a known refusal/rate-limit/server response. | `DirectDownloader.download` checks the final accepted HTTP status after its bounded 416 fallback and before any representation validation, retaining the concrete user-facing category. `errorStatusIsPreservedEvenWhenItsBodyIsHtmlOrCompressed` checks all four classes and staging preservation. No retry or authentication bypass was added. |
| **DL-03 / medium** | A parallel range probe or worker receives HTTP 429. The prior fallback would immediately request the full file from the origin. | Preserve HTTP 429 as a terminal transfer error and remove partial segments. `rateLimitStopsParallelDownloadWithoutAFullGet` covers both probe and worker responses, request counts, pre-existing staging and cleanup. |

Not verified by this workstream: a live 20-provider batch, every combination of batch failures, reboot during a real transfer, abrupt process/OS death while publishing to cloud or removable providers, radio handover/Doze, server throttling over public networks, live format availability, or controlled sustained throughput/battery measurements. Existing provider and archive behavior should be retested with the exact release candidate before production claims. Do not describe optional skips or historical CI as new execution.
