# Security audit — Android application boundaries

Mission baseline: `1e46c56ce6028bdbae51ae1f80091115cd614e0b` on `release/production-readiness`. This is an independent source inspection of the application security, networking and storage workstream, with a proposed remediation tested by deterministic fixtures. Build/run results are recorded centrally in [TEST_EVIDENCE.md](TEST_EVIDENCE.md); prior CI and packaging evidence is not a new test result.

## Findings and controls

| Boundary | Verified source behavior | Limit or disposition |
|---|---|---|
| URL parsing and SSRF | `Safety.kt` limits raw input, schemes and ports and rejects credentials and malformed/ambiguous literal addresses. The direct path validates literals before opening a call, disables system proxies, checks every DNS answer and follows only explicitly handled redirects with HTTPS downgrade protection. | No verified application SSRF bypass in reviewed paths. A local fixture is not an actual Android DNS64/VPN, custom NAT64, carrier or hostile-DNS test. A non-global-looking host name is not sufficient security without the resolved-address checks. |
| Native network path | `PublicProxy.kt` accepts only authenticated loopback CONNECT, validates the whole DNS answer, connects to those exact addresses and bounds concurrent tunnels and header time. `MediaEngine.kt` supplies the proxy and selected Android network. Native TLS remains end-to-end with the packaged trust store. `NativeProcessSession.kt` removes inherited proxy/CA override variables and uses structured argv. | Application proxy enforcement is not a kernel sandbox for native code. No all-extractor/FFmpeg egress certification or malicious certificate test was performed in this workstream. The native security/version and producer-lock risks in [SECURITY_REVIEW.md](../../SECURITY_REVIEW.md) remain open until independently closed. |
| HTTP error bodies | `DL-01` (medium): the old transfer path rejected HTML but would accept an explicit JSON, XML or plain-text error envelope under a known binary choice after a successful file probe. `OutputStore.validate` checked nonempty size for generic files, so staging integrity alone could verify the wrong bytes. | Implemented a type guard on successful sequential and parallel binary responses before any staging writes. Generic JSON/XML, absent MIME and opaque binary responses retain their previous acceptance. A deliberately mislabeled opaque body is not detected by this guard; same-size and SHA-256 checks certify the selected bytes, not their semantic format. |
| Output storage | Fixed per-task staging and sanitized names. `OutputStore` fingerprints staged bytes and compares destination content before commit. `PublicationReceipt` persists a write-ahead plan and rejects foreign or noncanonical returned SAF URIs; MediaStore rows start pending. | Authorized SAF providers are trusted to implement their rename and document identity contracts. Verified journal replay is not a test of power loss, hostile provider behavior, external volume removal or actual low-disk conditions. |
| Local state and diagnostics | `PrivateJournal` uses bounded AES-GCM records and authenticated journal format markers. `PipelineError.kt` allowlists diagnostic fields and writes debug-only logs without URLs, filenames or native tail text. Backup is disabled in manifest/configuration. | OS-level filesystem/keystore compromise, rollback, and underlying provider logs were not tested. |
| App entry and permission | Manifest exposes the launcher/share Activity and opt-in quick alias. The download service is not exported. The exported deferred job service requires system `BIND_JOB_SERVICE`. The quick path requires opt-in, a focused unlocked window and a bounded text clipboard item; sensitive clipboard flags and URI/intent items are rejected. | An exported launch intent does not cryptographically establish caller identity. The opt-in shortcut may analyze the selected public URL before a final confirmation; no verified cross-app exploit or unauthorized file write was reproduced. Real OEM shortcut and foreground clipboard behavior need device coverage. |

Public HTTP stays an explicit app-layer opt-in. The manifest cleartext allowance also supports the authenticated loopback proxy; no TLS verification, trust checks or SSRF controls were relaxed. The native path still accepts HTTPS source URLs only and rejects general HTTP proxy requests. No analytics, new permissions, accounts or tracking were added.

## Reproduction and regression coverage

For `DL-01`, enqueue a valid `HEAD` with `Content-Type: application/pdf`, followed by `GET 200` returning `application/problem+json` (or XML or text). The baseline's successful status and nonempty body would permit overwrite of staging; the replacement must leave its bytes untouched. A matching `206`, exact length, strong ETag and range must likewise be rejected if the body is explicitly incompatible with the chosen binary representation; preserve the checkpoint for a later valid response. See the two `DirectDownloaderTest` regressions in [DOWNLOAD_ENGINE_REVIEW.md](DOWNLOAD_ENGINE_REVIEW.md).

Source finding and changed boundaries: `DirectFileName.expectsBinary`, `DownloadService.transferTask`, `DirectDownloader.download`, `ParallelDownloader.download`, and `HttpRepresentation.requireIdentity`. Verification command: `./gradlew :app:testDebugUnitTest --tests 'com.os73.dosos73.DirectDownloaderTest' --tests 'com.os73.dosos73.HeaderRepresentationTest' --tests 'com.os73.dosos73.SafetyTest' --tests 'com.os73.dosos73.LiteralNetworkBoundaryTest' --tests 'com.os73.dosos73.PublicProxyTest' --tests 'com.os73.dosos73.ProxyLifecycleTest' --console=plain`.

Not verified here: hostile system DNS on a real device, network egress tracing across every extractor, certificate revocation on every ABI, USB/cloud SAF behavior, ENOSPC, device reset and crash recovery under actual interruptions, exploitability of inherited native advisories, or broad penetration testing. Keep production acceptance gated by the release decision and evidence rather than a clean scoped package scan.
